# ADR-005: LGPD Frontend Route Design

## Status

Accepted

## Date

2026-09-16

## Context

The LGPD feature needs a frontend presence. The current navigation has 6 sections (Visão geral, Estrutura, Pessoas, Portaria, Convivência, Operação, Administração) with items under each. LGPD operations (deletion requests, export, consent) are cross-cutting concerns that don't fit neatly into any existing section.

## Decision

Create a new navigation section **"Privacidade"** with a single item **"LGPD"** that routes to `/lgpd`. The page uses **tabs** to separate the three LGPD capabilities:

1. **Solicitações** (tab) — List of deletion requests with status, execute/cancel actions (admin only)
2. **Exportar** (tab) — Button to export personal data as JSON (resident) or for a specific resident (admin)
3. **Consentimento** (tab) — View and toggle consent status (resident); view-only for admins

The LGPD page is accessible to:
- **Residents**: Can see Export and Consent tabs; can create deletion requests from their profile
- **Sindico/Admin**: Can see all three tabs; can execute/cancel deletion requests

## Alternatives Considered

### Alternative 1: Section within Administração

- **Description**: Add "LGPD" as an item under the existing "Administração" section
- **Pros**: No new navigation section; familiar location for admins
- **Cons**: Residents need LGPD access but don't see "Administração" items (wrong permission scope); hides a compliance-critical feature among administrative items
- **Why rejected**: LGPD is a compliance feature, not an administrative setting; residents need direct access

### Alternative 2: Profile-only access (no sidebar)

- **Description**: LGPD operations only accessible through the resident's profile page
- **Pros**: No new routing; residents naturally find it in their profile
- **Cons**: Admins have no dedicated panel to manage deletion requests; no centralized compliance view; harder to discover
- **Why rejected**: Admins need a dedicated panel for deletion request management; a profile-only approach doesn't scale

### Alternative 3: Separate pages per LGPD capability

- **Description**: Three routes: `/lgpd/solicitacoes`, `/lgpd/exportar`, `/lgpd/consentimento`
- **Pros**: Each page is focused; simpler component logic
- **Cons**: Three route entries, three sidebar items, more navigation overhead for a feature with moderate complexity
- **Why rejected**: Tabs provide a better UX for closely related operations; reduces navigation clutter

## Consequences

### Positive

- Clear, dedicated location for compliance features
- Tabs provide logical grouping without overwhelming the sidebar
- Residents and admins see relevant tabs based on their role
- New "Privacidade" section can accommodate future privacy features

### Negative

- New navigation section adds one more item to the sidebar
- Tabs require careful UX to avoid confusion about which tab shows what

### Risks

- **Risk**: Residents may not find the LGPD page
  - **Mitigation**: Add a "Solicitar exclusão de dados" link in the resident's profile that navigates to the LGPD page's Export tab

## Implementation Notes

- Add `NAV_SECTIONS` entry: `{ title: 'Privacidade', items: [{ to: '/lgpd', label: 'LGPD', icon: Shield, permission: 'lgpd:read' }] }`
- Add `IMPLEMENTED` entry in `app-router.tsx`: `'/lgpd'`
- Create `src/features/lgpd/lgpd-page.tsx` with Radix Tabs
- Create three tab components: `lgpd-requests-tab.tsx`, `lgpd-export-tab.tsx`, `lgpd-consent-tab.tsx`
- Permission gating: `lgpd:read` for viewing, `lgpd:manage` for executing deletion requests
- Residents see only Export and Consent tabs; admins see all three
