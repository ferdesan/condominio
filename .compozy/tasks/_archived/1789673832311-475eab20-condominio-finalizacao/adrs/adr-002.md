# ADR-002: LGPD Data Export Format

## Status

Accepted

## Date

2026-09-16

## Context

LGPD Art. 18, III grants data subjects the right to data portability — the ability to export their personal data in a structured, commonly used format. The platform stores personal data across multiple entities (residents, dependents, employees, vehicles, correspondences, reservations, charges, payments) that would need to be consolidated into a single exportable package.

The export must be machine-readable (for portability to other systems) and must cover all personal data associated with the requesting data subject.

## Decision

Implement data export in JSON format as the primary and sole export format. The export endpoint will:

1. **Consolidate all personal data**: Gather data from all entities related to the requesting user (resident profile, dependents, vehicles, reservations, charges, payments, announcements addressed to them, documents they uploaded).
2. **Structure by entity**: Group data by entity type in a nested JSON structure with clear field names.
3. **Exclude system fields**: Omit internal IDs (`id`, `tenantId`), timestamps (`createdAt`, `updatedAt`), and soft-delete markers (`deletedAt`) from the export — include only user-meaningful data.
4. **Include metadata**: Add `exportDate`, `dataSubject`, and `platform` fields at the root level for context.
5. **No PDF**: JSON alone satisfies portability requirements; PDF adds implementation complexity without legal necessity.

## Alternatives Considered

### Alternative 1: JSON + PDF

- **Description**: Generate both machine-readable JSON and human-readable PDF for download
- **Pros**: PDF is more accessible for non-technical users; print-friendly
- **Cons**: Adds significant implementation complexity (PDF generation library, template management); LGPD does not require a specific format; JSON is sufficient for portability
- **Why rejected**: Unnecessary complexity; JSON is the standard for data portability (Art. 18, III says "structured, commonly used format")

### Alternative 2: CSV format

- **Description**: Export data in CSV format, one file per entity type
- **Pros**: Simple, widely supported by spreadsheet software
- **Cons**: Flat format cannot represent nested relationships (resident → dependents); multiple files complicate the download experience
- **Why rejected**: JSON better represents the hierarchical nature of the data

### Alternative 3: Multiple format options (JSON, CSV, XML)

- **Description**: Let the user choose their preferred export format
- **Pros**: Maximum flexibility
- **Cons**: 3x implementation and testing effort; LGPD only requires one "commonly used format"; JSON is the most universally supported for data portability
- **Why rejected**: Over-engineering; JSON alone meets the legal requirement

## Consequences

### Positive

- LGPD Art. 18, III compliance (data portability)
- Machine-readable format enables automated portability
- Simple implementation with no additional dependencies (JSON is native)
- Consistent with the platform's existing API response format

### Negative

- PDF is not available for users who want a printable document
- JSON may be less accessible for non-technical users (but the target audience is condominium administrators)

### Risks

- **Risk**: Export contains too much data, making it unwieldy
  - **Mitigation**: Structure the JSON clearly with entity-grouped sections; keep it focused on personal data only
- **Risk**: Export endpoint could be abused for bulk data extraction
  - **Mitigation**: Rate limit the endpoint; require authentication; only allow users to export their own data (enforced by tenant scope)

## Implementation Notes

- Create `GET /lgpd/export` endpoint that returns a JSON file
- The endpoint must be authenticated and tenant-scoped
- Residents can only export their own data (enforced by `residentId` from JWT)
- Admins/síndicos can export data for any resident in their condominium (for compliance requests)
- The JSON structure:

```json
{
  "exportDate": "2026-09-16T10:00:00Z",
  "platform": "Condominio SaaS",
  "dataSubject": { "name": "...", "email": "..." },
  "resident": { ... },
  "dependents": [ ... ],
  "vehicles": [ ... ],
  "reservations": [ ... ],
  "financial": {
    "charges": [ ... ],
    "payments": [ ... ]
  },
  "correspondences": [ ... ],
  "documents": [ ... ]
}
```

- Set `Content-Disposition: attachment; filename="lgpd-export-{residentId}-{date}.json"` for download
- Log the export in audit trail with action `LGPD_EXPORT`
