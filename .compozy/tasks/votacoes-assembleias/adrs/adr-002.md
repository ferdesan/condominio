# ADR-002: Record voter identity only on non-secret polls

## Status

Accepted

## Date

2026-09-22

## Context

`Vote.voterId` / `voterName` are nullable to support secret ballots. In the proxy path (`castVoteOnBehalf`) the code currently evaluates `poll.isSecret ? null : null`, which always stores null — open polls lose auditability of who cast the vote (resident self-vote already stores identity when not secret). Product decision required: is the vote attributable to a person or only to the unit?

## Decision

When `poll.isSecret` is **false**, persist `voterId` and `voterName` of the elector (resident self-vote: the authenticated resident; proxy registration: the unit's resident when known, otherwise null with `registeredByUserId` still recording the manager). When `poll.isSecret` is **true**, force both fields to null (and keep audit anonymous as today). Secret-poll API responses must not expose option choice beyond `{ voted: true }` on `my-vote`.

## Alternatives Considered

### Alternative 1: Always null (unit-only attribution)

- **Description**: Never store voter identity; vote always belongs to the unit.
- **Pros**: Minimal personal data (LGPD-friendly); simpler rules.
- **Cons**: Open polls lose who voted (market expectation: manager sees participation without revealing choice is enough, but audit/ata benefits); flag `isSecret` becomes meaningless for storage.
- **Why rejected**: User chose to register identity on non-secret polls for auditability.

### Alternative 2: Always store identity (ignore secret flag for storage)

- **Description**: Persist voter always; hide only in UI.
- **Pros**: Uniform storage.
- **Cons**: Breaks secret-ballot guarantees if storage is breached or mis-queried.
- **Why rejected**: Secret ballot must be enforced at write time, not only in the API layer.

## Consequences

### Positive

- Open polls are auditable; `isSecret` has real effect on write path.
- Fixes the inert ternary bug found in review (`poll.service.ts`).

### Negative

- Slightly more personal data on open polls — acceptable because the product treats open votes as attributable.

### Risks

- Proxy registration may not know which resident occupies a unit → store null resident identity and rely on `registeredByUserId` + unit number in audit.

## Implementation Notes

Fix `castVoteOnBehalf` / shared `persistVote` callers; extend backend integration tests for secret vs open storage and API exposure.
