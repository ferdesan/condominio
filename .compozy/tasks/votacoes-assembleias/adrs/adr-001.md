# ADR-001: Deep-link vote route as primary vote UX

## Status

Accepted

## Date

2026-09-22

## Context

Residents receive a notification when a poll opens with `actionUrl: /votacoes/${poll.id}`, but no frontend route exists, so the link is discarded. Polls are also listed inside the assembly "Deliberações" dialog, which today only offers create/edit/open/close/results — never a vote action. The product needs one canonical place where a resident casts a vote, reachable both from the notification and from the assemblies UI.

## Decision

Ship a dedicated frontend route `/votacoes/:pollId` (VotePage) as the primary voting surface. The same vote capability is also exposed as a "Votar" action inside `assembly-polls-dialog`, which navigates to (or opens) that route. Notification links resolve through `notification-links.ts` / `KNOWN_PATHS` so the existing backend `actionUrl` becomes clickable.

## Alternatives Considered

### Alternative 1: Vote only inside the assemblies dialog

- **Description**: Add a vote dialog nested under Deliberações; no new route.
- **Pros**: No router change; keeps everything under assemblies (ADR-004 of prior work).
- **Cons**: Notification deep link still dead; long vote flows in a nested dialog hurt mobile; no shareable URL.
- **Why rejected**: Fails the approved decision of route `/votacoes/:pollId` and leaves notifications broken.

### Alternative 2: Vote only on a standalone page (no dialog entry)

- **Description**: Only the route; assemblies list unchanged.
- **Pros**: Single surface.
- **Cons**: Users already browsing assemblies never discover the vote action without a notification.
- **Why rejected**: Missing entry from the existing Deliberações UX reduces participation.

## Consequences

### Positive

- Notification `actionUrl` works end-to-end.
- One vote surface to test and maintain; deep links work on mobile.
- Assemblies dialog gains a clear "Votar" affordance.

### Negative

- One more route and page component to register and permission-guard.

### Risks

- Guarding the route with the wrong permission hides the page from residents — mitigate with `vote:read` (or `assembly:read`) consistent with backend `my-vote`.

## Implementation Notes

Register in `app-router.tsx`; add path to `KNOWN_PATHS` / notification resolver. Keep ADR-004 (polls live in dialogs over the listing) for management; the vote page is the exception justified by deep links.
