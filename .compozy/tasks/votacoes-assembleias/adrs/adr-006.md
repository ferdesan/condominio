# ADR-006: DETAIL_PREFIXES preserves deep-link paths in notification resolution

## Status

Accepted

## Date

2026-09-22

## Context

`resolveActionUrl` walks path segments upward and returns the first candidate found in `KNOWN_PATHS` (`NAV_ITEMS` + `/perfil`). For `actionUrl: /votacoes/{pollId}` both `/votacoes/{id}` and `/votacoes` are unknown, so the link is discarded (`null` → "Sem tela de origem") — failing US-007 AC-1. Adding only `/votacoes` to `KNOWN_PATHS` would return `/votacoes` **without the poll id** (the walk returns the truncated candidate), landing on a non-existent route. The file's own design note rejected a full list of detail routes as a second router; a narrower exception is required.

## Decision

Introduce a small set `DETAIL_PREFIXES = ['/votacoes']` in `notification-links.ts`. In `resolveActionUrl`, before the upward walk: if the cleaned path equals a prefix or starts with `prefix + '/'` **and** the path has at least two segments (module + id), return the **full path** unchanged. Prefixes without an id segment, and paths outside the set, keep today's upward-walk behavior (listing fallback or `null`).

## Alternatives Considered

### Alternative 1: Return the raw path whenever the first segment is known

- **Description**: If `segment[0]` is in `KNOWN_PATHS`, return the whole `actionUrl`.
- **Pros**: No new set.
- **Cons**: Breaks the documented fallback: `/reservas/{id}` would become a dead link instead of collapsing to `/reservas` — exactly the blank-screen class this module exists to prevent.
- **Why rejected**: Collateral damage to every non-registered detail path.

### Alternative 2: Add `/votacoes` only to `KNOWN_PATHS`

- **Description**: Rely on the existing walk.
- **Pros**: One-line change.
- **Cons**: Returns `/votacoes` without `{pollId}`; US-007 AC-1 requires `/votacoes/:id`.
- **Why rejected**: Wrong destination.

### Alternative 3: Register full route patterns (regex) mirroring the router

- **Description**: Duplicate every dynamic route as a pattern.
- **Pros**: Fully general.
- **Cons**: Second source of truth for the router; forgetting a pattern silently drops links — the failure mode the module doc already rejected.
- **Why rejected**: Overkill for one deep-link family today.

## Consequences

### Positive

- Notification deep links land on the real vote page with the poll id; existing listing fallback untouched.

### Negative

- Each new parameterized notification destination must add its prefix here (one line, documented).

### Risks

- Prefix collisions (`/votacoes-antigas` vs `/votacoes`) — mitigate by matching `path === prefix || path.startsWith(prefix + '/')` only.

## Implementation Notes

Update the module doc comment: the single upward rule remains the default; `DETAIL_PREFIXES` is the sanctioned exception for routes that must keep their id. Cover with unit tests on `resolveActionUrl`.
