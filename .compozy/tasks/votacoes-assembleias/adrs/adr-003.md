# ADR-003: Manual vote registration is per unit, with a status list

## Status

Accepted

## Date

2026-09-22

## Context

Síndicos still receive paper votes or verbal instructions at the assembly. The backend already exposes `POST /polls/:id/votes` (`vote:manage`) with `{ unitId, optionId }`. Competing platforms expect a manager view of **who has voted without revealing the choice**, plus a way to enter a vote for a unit that could not use the app. Product decision: granularity of manual registration and what the list shows.

## Decision

Manual registration is **per unit** (one row per unit of the poll's condominium). The management dialog lists every eligible unit with status **Already voted** / **Pending** / **Not eligible** (e.g. `voterType: OWNERS` and resident is not an owner). Status does **not** disclose the chosen option. From a pending row the manager selects an option and submits; backend enforces uniqueness (409) and janela. Access requires `vote:manage` (ADMIN/SINDICO).

## Alternatives Considered

### Alternative 1: Manual registration per resident/person

- **Description**: Pick a person, not a unit.
- **Pros**: Matches some procuração workflows.
- **Cons**: Domain index and rules are per unit; conflicts with one-vote-per-unit; out of scope (no procuração).
- **Why rejected**: Plan approved management **by unit**; person-level proxy is a Non-Goal.

### Alternative 2: Status list with registrar trail visible in the same dialog

- **Description**: Also show who registered proxy votes and when.
- **Pros**: Full audit in UI.
- **Cons**: Larger scope; audit already exists server-side; not requested.
- **Why rejected**: YAGNI for this iteration — status-only list approved.

## Consequences

### Positive

- Manager can chase pending units; respects secret ballot (no option leak).
- Aligns with backend contract and unique index.

### Negative

- Units not listed as "not eligible" need clear labeling to avoid confusion.

### Risks

- Large condominiums (hundreds of units) need filtering by status — include a simple status filter in the dialog.

## Implementation Notes

Frontend dialog `poll-proxy-votes-dialog.tsx`; hook `useCastProxyVote`; may need a read endpoint that returns unit + voted flag (derive from votes list + units, or a dedicated summary — TechSpec decides).
