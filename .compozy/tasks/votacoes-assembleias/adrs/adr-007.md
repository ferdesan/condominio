# ADR-007: Server enforces OWNER eligibility on manager registration

## Status

Accepted

## Date

2026-09-22

## Context

`castVote` (resident path) rejects non-owners when `poll.voterType === 'OWNERS'`. `castVoteOnBehalf` (manager path) does not load residents at all: any unit in the same condominium can receive a proxy vote. ADR-003 requires status **Not eligible** in the management list and states the server remains authority for that rule — otherwise the dialog can show NOT_ELIGIBLE while `POST /polls/:id/votes` still succeeds, and the two surfaces disagree.

## Decision

Before persisting a proxy vote, if `poll.voterType === 'OWNERS'`, load active OWNER residents for `dto.unitId` (same tenant/condominium scope). If none exist, throw `ForbiddenError` (403) with a clear message. `ALL_RESIDENTS` polls keep today's behavior (any unit of the condominium is eligible). The status endpoint (ADR-005) and this check share the same definition: unit eligible ⇔ `ALL_RESIDENTS`, or (`OWNERS` and ≥1 active OWNER resident on the unit).

## Alternatives Considered

### Alternative 1: Client-side only (status informs, server allows)

- **Description**: Dialog hides submit on NOT_ELIGIBLE; backend unchanged.
- **Pros**: Zero backend risk.
- **Cons**: Server is not authority; API clients and races bypass the rule; contradicts ADR-003 EC-2.
- **Why rejected**: User chose server enforcement 2026-09-22.

### Alternative 2: Relax status to match backend (drop NOT_ELIGIBLE)

- **Description**: Treat every unit as pending until voted.
- **Pros**: Simpler list.
- **Cons**: Manager wastes time on units that cannot vote on an OWNERS poll; product already approved the third status.
- **Why rejected**: ADR-003 fixed the three-state list.

## Consequences

### Positive

- One eligibility definition for status display and for both write paths; API cannot register an illegal proxy vote.

### Negative

- Proxy path gains a resident lookup (one query when OWNERS; none when ALL_RESIDENTS).

### Risks

- Units with no resident rows on an OWNERS poll become unregistrable by proxy — correct per rules; manager sees NOT_ELIGIBLE and does not attempt submit.

## Implementation Notes

Share a private helper (e.g. `assertUnitEligible` / `unitHasOwner`) used by `castVoteOnBehalf` and `voteStatus`. Identity for non-secret proxy votes (ADR-002) may reuse the same resident lookup (prefer primary active resident).
